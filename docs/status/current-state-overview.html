The boundary is the design

Android objects stop at the platform edge. Everything deeper receives immutable records and returns typed results.

:host:platform

Framework adapters

LauncherApps, UserHandle, SAF imports, icon resources, wallpaper, Settings routes, drawables, and host views live here.

→
:host:runtime + :host:data

Policy and coordination

Profile filtering, search, theme resolution, typed execution, lifecycle ledgers, store transactions, and asset cleanup decisions.

Contribution modules

Sanitized rendering

Stable IDs, semantic kinds, prepared content, resolved colors/fonts/icons, contrast, work badging, and opaque tokens only.

No Android callbacks, Room records, raw queries, contact/file content, locked private metadata, or mutable collections cross this line.

Implemented capability map

Phase 7 is complete. One resolved host-owned theme contract is consumed by every host and contribution surface.

Widget lifecycle

Ready

One durable ID per placement, one live view per surface, and recoverable cleanup across framework and database boundaries.

  • Bind, configure, resize, copy, dormancy
  • Restart, restore, invalidation, deletion
  • Cancellation and rejected-commit leak checks

Shortcuts

Ready

Profile-aware semantic identity with distinct placement identity and complete pinned-set reconciliation.

  • Duplicate placements survive Room reopen
  • Stale and locked targets fail closed
  • Launch resolves current profile state

Profiles + Private Space

Ready

Profiles are classified before metadata access. The private container is host-owned, secure, and absent when policy is unclear.

  • API 36 visibility configuration and settings route
  • System authentication and asynchronous unlock
  • Immediate labels, icons, results, and indicator purge

Notification indicators

Ready

The platform reduces notifications to eligible profile/package aggregates. No notification content leaves the adapter or reaches storage.

  • None, dot, or approximate count
  • Denial, revocation, disconnect, recovery
  • API 37 framework revocation race handled

Folders

Ready

Stable folders retain explicit order and durable hidden members while the open overlay filters current policy.

  • Create, rename, reorder, delete
  • Keyboard, D-pad, TalkBack alternatives
  • Back, Home, and process recreation

Item actions

Ready

Every action revalidates the current item, package, profile, and policy before execution.

  • Favorite, visibility, rename, folders
  • Details, uninstall, disable, shortcut removal
  • Typed rejection and destructive confirmation

Search engine

Ready

One bounded session per presentation with concurrent providers, partial publication, provider-local isolation, and strict generation ownership.

  • Debounce, replacement, timeout, cancellation
  • Immutable deterministic snapshots
  • Stale and post-close output rejected

Search privacy

Ready

Profile classification precedes metadata. Work badging is mandatory and ambiguous private data never enters a session or history.

  • Permission-local denial and recovery
  • Immediate callback-driven result purge
  • App/shortcut-only bounded history

Production providers

Ready

Nine generated-registry providers cover apps, shortcuts, commands, contacts, authorized files, Settings, GrapheneOS, web, and recovery information.

  • Exact Settings route revalidation
  • Persisted SAF grants and runtime contacts
  • Encoded exact-host HTTPS actions

Theme system

Ready

One host resolver supplies the immutable theme used by Material surfaces, Settings, production composition, cold restore, previews, layouts, and blocks.

  • Built-in, Material You, Expressive, manual
  • Bounded fonts, icons, images, backgrounds
  • Explicit typed wallpaper confirmation
