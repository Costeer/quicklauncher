# Reserve a host-owned safe layout identity

The launcher persists `org.quicklauncher.core/safe-layout` as the reserved contribution and configuration type for its non-removable safe layout. The host renders this emergency surface directly instead of dispatching it through the generated contribution registry, so app launching, local app filtering, map overview, Settings, and recovery remain available when optional code, configuration loading, or the later composition engine fails. App visibility policy is read independently from the launcher map aggregate. If that policy itself is unavailable, the ordinary app collection fails closed rather than revealing hidden apps; the host Settings surface retains a typed recovery list built from platform launch identities, where hidden apps are intentionally recoverable. Every destination receives one retained safe-layout root with host-generated stable instance and configuration-document IDs. This exception trades registry uniformity for a recovery path that cannot depend on the subsystem it repairs; optional modules cannot register, replace, remove, or reinterpret the reserved identity.
